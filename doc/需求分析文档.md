# Word协议表格信息智能提取与匹配系统 - 需求分析文档

## 一、项目概述

### 1.1 项目定义

本项目是一个**Word协议表格信息智能提取与匹配系统**，用于从Word文档中自动识别和提取表格信息，并将提取的数据字段智能匹配到标准目标字段，最终生成标准化的Excel输出。

### 1.2 核心目标

- **自动识别**：使用程序自动识别Word文档中的表格
- **智能提取**：提取表格中的关键信息（信息名称、内容、转换类型等）
- **字段匹配**：通过知识库、模型或人工干预实现字段映射
- **标准化输出**：生成规范的Excel格式结果
- **知识积累**：所有匹配结果保存到知识库，支持后续复用和模型优化

### 1.3 开发规划

- **第一期**：知识库精确匹配 + 人工干预系统（当前阶段）
- **第二期**：语义匹配引擎 + 智能推荐系统（预留扩展）

### 1.4 技术栈

| 组件 | 技术 |
|------|------|
| 前端框架 | Vue 3 + TypeScript |
| 后端语言 | Python + Flask |
| 数据存储 | 本地JSON文件 + 文件锁 |
| 表格解析 | python-docx、openpyxl |
| 任务处理 | Python threading（后台线程） |
| API响应格式 | RESTful + JSON |
| 文件格式支持 | .doc、.docx、Excel、CSV |

### 2.2 表格识别与提取方案

#### 2.2.1 自动识别流程

系统优先使用程序自动识别表格：

1. **表格定位**：通过python-docx库扫描Word文档中的所有表格对象
2. **有效性判断**：根据表格特征判断是否为有效的信息表（列数、关键字等）
3. **表头识别**：使用多策略识别表头位置
4. **数据提取**：提取表头和对应的行数据

#### 2.2.2 多策略表头识别

当自动识别失败时，采用以下策略协同处理：

**策略一：协议模板判断**
- 检查表格是否包含标准列数（如4列）
- 检查是否存在特定关键字（如"数据类型"、"单位"等）
- 使用协议模板中定义的特征进行匹配

**策略二：文本特征识别**
- 识别特定行数格式的表头（如第5行为特定格式）
- 通过行内容的通用特性识别表头
- 识别包含特定词汇的行作为表头

**策略三：行数结构变化识别**
- 对于行数较多的表格，从倒数第二行向上搜索
- 寻找行数、列数发生显著变化的区域
- 该区域通常标记为表头与正文的分界线

#### 2.2.3 人工干预机制

当程序无法准确识别表格时：

1. **触发人工处理界面**：前端显示表格预览和拖拽修正工具
2. **用户修正**：允许用户通过拖拽操作调整表格区域
3. **反馈保存**：将用户修正结果保存为优化策略的训练数据

### 2.3 字段提取与处理规则

#### 2.3.1 必需字段定义

提取的数据模板中，每一项信息记录包含以下字段：

| 字段名 | 类型 | 必需 | 说明 |
|--------|------|------|------|
| 信息名称 | String | 是 | 字段在原表中的名称 |
| 内容 | String | 是 | 字段的实际取值或说明 |
| 转换类型 | String | 是 | 数据类型转换规则 |
| 单位 | String | 否 | 数据单位（如"米"、"秒"） |
| 判读公式 | String | 否 | 数据处理或转换公式 |
| 备注 | String | 否 | 额外说明 |

#### 2.3.2 缺失字段处理

当提取的信息缺失上述必需字段时的处理方式：

**情况1：缺失"信息名称"**
- 使用信息的"内容"字段起一个临时名称
- 标记此记录需要人工审核
- 示例：内容为"integer"→ 临时名称"参数_类型_1"

**情况2：缺失"内容"**
- 将此字段标记为异常
- 在输出Excel中添加异常标记或特殊标记
- 便于后续定位和检查

**情况3：缺失"转换类型"**
- 根据"内容"字段推断（如"123"→"int"）
- 如无法推断则使用默认值"string"
- 标记为需要人工验证

#### 2.3.3 特殊列处理规则

**单位列**
- 直接原样填入Excel，无需转换
- 保留原始的度量衡单位、时间单位等

**判读公式/转换公式列**
- 需要结构化提炼值域和运算规则
- 提取规则形式：`ax+B` 或 `f(x) = ...`
- 示例：
  - 原始："湿度值 * 0.1 + 20"
  - 提炼："x * 0.1 + 20"，值域："[0-1023] → [-20, 82.3]"

**备注列**
- 保留原始内容，不做处理
- 如备注过长（>500字符）需在Excel中使用超链接或备注框

#### 2.3.4 数据清洗与异常处理

| 异常情况 | 处理方式 | 输出标记 |
|---------|---------|---------|
| 字段值为空 | 保留空值或填"N/A" | "缺失值" |
| 类型转换错误 | 保留原始值，标记异常 | "类型错误" |
| 重复字段名 | 添加序号区分 | "字段名_1"、"字段名_2" |
| 特殊字符编码错误 | 尝试修复，失败则保留原值 | "编码异常" |
| 多表关联缺失键值 | 标记关联失败 | "关联失败" |

### 2.4 通信协议字段内置方案

#### 2.4.1 协议字段预置

系统内置常用的通信协议字段选项，用户可直接使用，无需每次手动配置：

**标准协议字段清单**

| 分类 | 字段名 | 别名 | 说明 |
|------|--------|------|------|
| 协议基本 | 协议名 | 协议ID、协议标识 | 协议的唯一标识 |
| 协议基本 | 协议版本 | 版本号 | 协议版本信息 |
| 数据结构 | 数据类型 | 参数类型、变量类型 | 参数或字段的数据类型 |
| 数据结构 | 单位 | 测量单位 | 数据的度量单位 |
| 数据流向 | 输入参数 | 入参、方法参数、输入 | 协议的输入参数 |
| 数据流向 | 输出参数 | 出参、返回值、输出 | 协议的输出参数 |
| 取值范围 | 值域 | 范围、最大值/最小值 | 参数的取值范围 |
| 转换规则 | 转换公式 | 计算公式、判读公式 | 数据转换或计算规则 |
| 元数据 | 备注 | 说明、描述 | 额外说明信息 |
| 元数据 | 源表ID | table_id、来源 | 数据来源的表格标识 |

#### 2.4.2 协议字段配置管理

用户可在"字段配置"页面进行以下操作：

1. **查看预置字段**：查看所有内置的标准协议字段
2. **自定义扩展**：添加项目特定的新字段

## 四、数据结构与API接口

### 4.1 知识库数据结构

#### 4.1.1 知识库表定义

```sql
CREATE TABLE knowledge_base (
    id INT PRIMARY KEY AUTO_INCREMENT,
    source VARCHAR(255) NOT NULL,             -- 源字段（协议字段）
    target VARCHAR(255) NOT NULL,             -- 目标字段
    table_id VARCHAR(255),                    -- 来源表格ID（可选）
    confidence FLOAT DEFAULT 1.0,             -- 置信度 [0.0-1.0]
    hits INT DEFAULT 1,                       -- 命中次数
    label_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,  -- 标注时间
    labeler VARCHAR(255),                     -- 标注者ID
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY unique_mapping (source, target, table_id)
);
```

#### 4.1.2 数据字段说明

| 字段名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| id | INT | 主键 | 1 |
| source | VARCHAR(255) | 源字段（协议字段）| "协议名" |
| target | VARCHAR(255) | 目标字段（目标表头）| "协议名称" |
| table_id | VARCHAR(255) | 来源表格ID | "BC-RT1" |
| confidence | FLOAT | 置信度 | 1.0、0.85 |
| hits | INT | 使用次数 | 5、12 |
| label_time | TIMESTAMP | 标注/更新时间 | 2024-12-20 10:30:00 |
| labeler | VARCHAR(255) | 标注者ID | "user_001" |
| created_at | TIMESTAMP | 创建时间 | 2024-12-20 10:30:00 |
| updated_at | TIMESTAMP | 更新时间 | 2024-12-20 10:30:00 |

#### 4.1.3 示例数据

```
ID | source | target | table_id | confidence | hits | label_time | labeler
1  | 协议名 | 协议名称 | BC-RT1   | 1.0        | 5    | 2024-12-20 | user_001
2  | 输入参数 | 入参 | BC-RT1   | 1.0        | 3    | 2024-12-20 | user_001
3  | 输出参数 | 出参 | BC-RT1   | 1.0        | 2    | 2024-12-20 | user_001
4  | 参数类型 | 数据类型 | BC-RT1 | 0.9        | 1    | 2024-12-21 | user_002
```

## 五、字段匹配分层策略

### 5.1 匹配优先级

系统采用分层匹配策略，按以下优先级依次尝试：

```
┌─ 第一层：知识库精确匹配 ──→ 置信度=1.0 ──→ 直接使用
│
├─ 第二层：模型语义匹配(二期) → 置信度≥0.85 ──→ 自动使用 或 推荐确认
│
├─ 第三层：模型推荐(二期) ──→ 置信度=0.7-0.85 ──→ 显示推荐
│
└─ 第四层：人工干预 ───────→ 触发拖拽界面
```

### 5.2 匹配场景与处理

#### 场景1：精确匹配成功（知识库命中）

- **触发条件**：在知识库中找到完全匹配的映射
- **处理方式**：直接自动转换，无需人工介入
- **置信度**：1.0
- **标记**：无标记

#### 场景2：模型推荐成功（二期功能）

- **触发条件**：模型计算相似度≥0.85
- **处理方式**：自动转换，或显示推荐等待用户确认
- **置信度**：模型相似度值
- **标记**：根据用户操作标记为"推荐确认"或无

#### 场景3：模型推荐置信度低

- **触发条件**：模型相似度<0.7
- **处理方式**：转人工干预流程，提供拖拽或输入界面
- **置信度**：1.0（人工干预）
- **标记**：无标记

#### 场景4：人工干预处理

- **触发条件**：自动匹配失败或模型推荐不合适
- **处理方式**：用户通过拖拽或输入方式手动匹配
- **置信度**：1.0（人工标注）
- **标记**：无标记

### 5.3 版本管理与冲突处理

当同一个字段映射存在多个版本时（如不同团队或时期的标注）：

1. **版本隔离**：通过table_id或version_id隔离不同版本
2. **优先级判定**：
   - 人工标注（confidence=1.0）> 模型推荐（confidence<1.0）
   - 较新标注优先使用
   - 高frequency映射优先使用
3. **冲突告警**：
   - 同一source字段映射到多个target时告警
   - 用户可选择手动确认正确映射

## 六、数据质量与异常处理

### 6.1 数据验证规则

#### 表格级验证

| 验证项 | 规则 | 失败处理 |
|--------|------|---------|
| 表格是否为空 | 至少包含1行数据 | 标记为无效表 |
| 列数一致性 | 所有行列数相同 | 提示表格异常，人工干预 |
| 表头识别 | 识别表头行 | 多策略尝试 |
| 必需列存在 | 至少包含一列 | 提示并人工干预 |

#### 字段级验证

| 验证项 | 规则 | 失败处理 |
|--------|------|---------|
| 必需字段完整 | 名称+内容+类型 | 缺失补全或标记异常 |
| 类型转换正确 | 数据符合转换类型 | 标记"类型错误" |
| 特殊字符编码 | 正确编码显示 | 尝试修复或保留原值 |
| 公式格式合理 | 公式语法正确 | 结构化提炼 |

### 6.2 异常类型与处理

#### 异常1：字段值为空

**表现**：提取的某个字段为空
**原因**：源表中该字段未填或格式异常
**处理**：
- 在Excel中显示"N/A"或空值
- 添加备注提示
- 重新人工检查

#### 异常2：类型转换失败

**表现**：无法将字段值转换为指定类型
**原因**：值与类型不匹配（如"abc"转int失败）
**处理**：
- 保留原始值（字符串）
- 标记"类型错误"
- 待人工审核后修正

#### 异常3：重复字段名

**表现**：两个不同的字段有相同的名称
**原因**：源表设计问题或提取算法误识别
**处理**：
- 添加序号：原名称_1、原名称_2
- 标记为需要人工审核
- 记录到异常日志

#### 异常4：特殊字符编码错误

**表现**：显示为乱码或符号错误
**原因**：文件编码不统一或字体缺失
**处理**：
- 尝试UTF-8、GBK等编码转换
- 失败则保留原始数据
- 标记"编码异常"

#### 异常5：多表关联失败

**表现**：应该匹配的多个表无法找到共同键值
**原因**：键值命名不一致或数据缺失
**处理**：
- 标记"关联失败"
- 显示无法关联的表信息
- 提供人工关联选项

### 6.3 异常输出与可追溯性

#### Excel输出异常标记

在生成的Excel中添加"质量标记"列，标注以下信息：

| 标记 | 含义 | 处理建议 |
|------|------|---------|
| ✓ | 正常（精确匹配或人工审核） | 无需处理 |
| ⚠️ | 推荐确认（模型推荐） | 需验证 |
| ❌ | 异常（缺失、类型错误等） | 需人工修正 |
| ? | 低置信度（模型相似度低） | 需人工确认 |

#### 异常日志

系统记录所有异常，包括：
- 异常类型和描述
- 发生时间
- 涉及的表格和字段
- 处理结果
- 操作员信息
