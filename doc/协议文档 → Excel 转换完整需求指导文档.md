## 三、源表的三种结构类型

经过分析，源文档中的有效字段定义表可归纳为以下三种结构，每种结构的**表头行数、列排列、列名称各不相同**，代码必须能适配所有情况。

### 类型A：标准分布式字段表（多行表头 + 信息名称行）

**代表**：源表 #7（测量数据1）、#8（测量数据2）、#16（测量数据7）等

**结构特征**：
- 第0行：信息名称行（含 `信息名称`、消息名称值、`信息标识` 等，大量列合并）
- 第1行：列名行（代号、内容、类型、字节、值域、数据处理、单位、备注等）
- 第2-N行：数据行（每行一个字段）

**源表 #7 完整内容示例**：
```
行0: ['信息名称'(→2列), '信息名称'(→2列), '某设备装置测量数据1'(→2列), '某设备装置测量数据1'(→2列), '信息标识', '信息标识', '—', '—', '—']
行1: ['代号', '内容', '内容', '类型', '字节', '值域', '数据处理', '单位', '备注']

行3: ['Counter', '帧计数', '帧计数', 'UINTEGER-32', '4', '0~4294967295', '', '—', '乘以10']
```

**提取逻辑**：
- 消息名称：从第0行中找到不是固定表头词（`信息名称`、`信息标识`、`—`）的合并单元格值
- 数据行：从第2行起，每行提取字段信息
- 内容字段：取"内容"列（合并列取第一个非空值）
- 类型：取"类型"列，做标准化（见第六节）
- 字节数：取"字节"列，×8得到bit数
- 值域：取"值域"列
- 转换公式：取"数据处理/数据转换方法"列
- 单位：取"单位"列
- 备注：取"备注/说明"列

**源表 #8 的变体（多一列"区间"）**：
```
行0: ['信息名称', '信息名称', '某设备装置测量数据2', '某设备装置测量数据2', '信息标识', '信息标识', '—', '—', '—', '—']

## 四、特殊结构表的处理

### 4.1 聚合式消息表（源表 #4，检查结果）

这类表的特殊之处在于，**消息本身就包含了子地址、数据段长度等聚合协议属性**，这些信息需要填入 Excel 对应列。

**源表 #4 完整内容**：
```

行1: ['信源、信宿'(→2列), 'BCRT1-SA0-模式码0x03'(→6列)]
行2: ['传输周期'(→2列), '非周期'(→2列), '其他', '-'(→3列)]
行3: ['序号', '内容', '类型', '字节数', '取值范围', '单位', '说明', '说明']
行4: ['', '计时时间', 'UINTEGER-32', '4', '0~4294967295', 'ms', '32位整型数...', '32位整型数...']
```

**提取逻辑**：
- 消息名称：`检查结果`（行0中提取）
- 信源机器码：从 `BCRT1-SA0-模式码0x03` 中解析 → `BC`
- 信宿机器码：解析 `RT1` → `1`
- 子地址：解析 `SA0` → `0`
- 数据段长度：解析 `模式码0x03` → `3`
- 这些信息会填充到 Excel 的子地址、数据段长度列

**Excel中的输出（行4-5，重复两行）**：
```

- 位号 `bit6:5` → 类型(bit) = 2（2个bit）

行38: 子内容='状态4' | 类型=1 | 转换类型='UINT8'                   ← bit7 = 1bit

**注意**：
- `信道状态` 行的子内容列填写了 `False`（这是一个特殊值，表示"此行本身无子内容名"，但有子行）

## 六、字段数据的处理规则

### 6.1 数据类型标准化（转换类型列）

源表中"数据类型"列的写法各异，需统一标准化：

| 源表写法 | 标准化结果 |
|---------|---------|
| `UINTEGER-32` | `UINT32` |
| `UINTEGER-16` | `UINT16` |
| `UINTEGER-8` | `UINT8` |
| `USHORT` | `UINT16` |
| `UINT8` | `UINT8`（已标准，不变） |
| `字节` | `UINT8` |
| `FLOAT` | `FLOAT32` 或 `FLOAT`（视需求定） |

**规则**：
- 去掉 `UINTEGER-` 前缀，补 `UINT`
- `USHORT` = 16bit = `UINT16`
- `字节` = 8bit = `UINT8`

### 6.2 类型(bit) 的计算规则

| 来源 | 计算方式 |
|------|--------|
| 源表有"字节数"列 | `字节数 × 8` |
| 源表有"数据长度（字节）"列 | `字节数 × 8` |
| 源表有"长度"列（如字节长度） | `字节数 × 8` |
| bit位定义表中的"位号"列 | 解析 bit 范围，例如 `bit7` = 1，`bit6:5` = 2，`bit4:1` = 4 |

### 6.3 值域处理规则（判读公式列）

这是最复杂的处理规则，分为三层：

#### 第一优先级：源表中有"值域"列且列值不为空

直接使用源表值域列的值，并进行格式转换：

| 源表值域 | 转换后 | 说明 |
|---------|------|------|
| `0~4294967295` | `[0,4294967295]` | 默认闭区间，用 `[]` 表示 |
| `0~65535` | `[0,65535]` | 同上 |
| `0~255` | `[0,255]` | 同上 |
| `0~400` | `[0,400]` | 同上 |
| `[0,255]` | `[0,255]` | 已是标准格式，直接使用 |
| `(0,6)` | `(0,6)` | 备注明确为开区间，保留 |
| `0~0xFFFF` | `[0,65535]` | 16进制 0xFFFF → 十进制 65535 |
| `0~0xFF` | `[0,255]` | 16进制转换 |
| `0~0x6` | `[0,6]` | 16进制转换 |

**格式转换逻辑**：
1. 如果已经包含 `[` 或 `(` 开头，说明已是区间格式，直接使用
2. 否则识别 `a~b` 格式，转为 `[a,b]`
3. 其中若 a 或 b 包含 `0x` 前缀，做十六进制到十进制转换
4. 若备注中明确写了开区间（如 `(a,b)`），则使用开区间格式 `(a,b)`，否则默认闭区间 `[a,b]`

#### 第二优先级：源表中无"值域"列，或值域列为空，从备注列提取

此时从"备注/说明"列中用正则表达式提取数值范围：

- 正则匹配模式：`(\d+|0x[0-9a-fA-F]+)\s*~\s*(\d+|0x[0-9a-fA-F]+)`
- 也匹配：`取值范围\s*(\d+)\s*~\s*(\d+)` 等带前缀的格式
- 同样执行 16 进制到十进制转换
- **同样应用开/闭区间规则**：若备注有明确区间格式保留，否则默认闭区间

**来自备注提取的值域，写入判读公式列时，必须用红色字体标记**

#### 第三优先级：既无值域列也无可提取的备注

判读公式列保持空白

### 6.4 转换公式列的处理规则

源表中"数据处理"或"数据转换方法"列的写法需要标准化：

| 源表写法 | Excel转换公式 |
|---------|------------|
| `乘以10` | `10x` |
| `乘以10` | `10x+0`（加偏移0的写法也可接受） |
| `0x000000477*x+0`（源表已经给出了公式） | 直接使用 |
| 空 | 空 |

### 6.5 单位列的处理规则

- `—`（长破折号）或 `—`（短破折号）→ 输出为空或不输出
- `ms`、`°/h` 等直接保留
- 若单位为空但备注中有物理单位说明，可选择不提取（备注列保留完整说明）

### 6.6 备注列的处理规则

- 直接复制源表备注/说明字段内容
- **不要包含值域信息**（值域已提取到判读公式列）
- 若备注内容与值域内容高度重复，仍然保留完整备注（判读公式里的值域只是额外提取的）

## 七、主行与子行的构建规则

### 7.1 主行的定义

每个"消息/数据结构"输出**一个主行**，主行特征：
- `名称` 列有值（消息名称）
- `信源系统码`、`信源机器码`、`信宿系统码`、`信宿机器码` 根据端口分配表填充
- `ID` 列有值（消息ID）
- `内容` 列填写**该消息的第一个字段名**
- 其余字段列（类型、转换类型、判读公式等）填写第一个字段的对应值

**主行 = 消息元数据 + 第一个字段的内容**

### 7.2 子行的定义

同一消息的**第二个字段开始**，每个字段输出一个子行，子行特征：
- `名称` 列**为空**（即继承上一主行的名称）
- `信源系统码`、`信源机器码`、`信宿系统码`、`信宿机器码`、`ID` 列全部**为空**
- `内容` 列填写该字段名
- 其余字段列正常填写

### 7.3 主行实例

**源表 #7（某设备装置测量数据1）→ Excel 行2、行3**：

```
源表:
  消息名称 = 某设备装置测量数据1 (来自行0的合并单元格)
  字段1 = 某设备计时时间, UINTEGER-32, 4字节, 0~4294967295, ms, 32位整型数...
  字段2 = 帧计数, UINTEGER-32, 4字节, 0~4294967295, —, 乘以10

端口分配表(源表#2):
  某设备装置测量数据1 → 信源系统码=100, 信源机器码=128, 信宿系统码=100, 信宿机器码=111

消息ID表(源表#3):
  某设备装置测量数据1 → ID=0x8000

Excel 主行 (行2):
  名称=某设备装置测量数据1, 信源系统码=100, 信源机器码=128, 信宿系统码=100, 信宿机器码=111,
  子地址=(空), 数据段长度=(空), ID=0x8000,
  内容=某设备计时时间, 子内容=(空), 类型(bit)=32, 转换类型=UINT32,
  判读公式=[0,4294967295], 转换公式=(空), 单位=ms,
  备注=32位整型数，LSB=1ms，以上电为零点，软件开算时刻清零

Excel 子行 (行3):
  名称=(空), 信源系统码=(空), ...全部为空..., ID=(空),
  内容=帧计数, 子内容=(空), 类型(bit)=32, 转换类型=UINT32,
  判读公式=[0,4294967295], 转换公式=10x, 单位=(空),
  备注=乘以10
```

## 八、多表联合的详细规则

### 8.1 端口分配信息 + 消息ID + 字段定义（三表联合）

**适用消息**：所有在端口分配表中有记录的消息

**联合步骤**：
1. 读取源表#2，建立字典：`消息名 → {信源系统码, 信源机器码, 信宿系统码, 信宿机器码}`
2. 读取源表#3，建立字典：`消息名 → 消息ID`
3. 读取每个字段定义表，从表头提取消息名，查找步骤1和2的字典获取辅助信息
4. 输出时合并所有信息

### 8.2 综合状态数据 + 信道状态bit定义（两表联合）

**适用消息**：综合状态数据

**联合步骤**：
1. 读取源表#18，获取字段列表（电压、电流、信道状态）
2. 读取源表#19，获取 bit 位定义（状态4、状态3、状态2、状态1）
3. 判断：`信道状态` 字段对应了 bit 位定义
4. 在"信道状态"字段输出一行（内容=信道状态，子内容=False）
5. 紧接着输出所有 bit 位（子内容填写 bit 名，内容为空）

**如何判断某字段有 bit 位定义**：
- 存在一个 bit 位定义表（标题通常含"某字段状态"或 `表B.1XXX`），其定义的是前一个表中某字段的内部结构
- 或者某字段的备注中说明了 bit 结构（如 `bit7-0定义如下`）

### 8.3 聚合式消息表的处理

**适用消息**：`检查结果`（源表#4）

- 信源/信宿/子地址等信息直接从表中解析，不依赖端口分配表
- 解析格式：`BCRT1-SA0-模式码0x03` → BC=信源机器码, RT1=信宿机器码(1), SA0=子地址(0), 模式码0x03=数据段长度(3)

## 九、表格识别与筛选规则

代码需要自动判断一个源表是否需要提取，判断规则如下：

### 9.1 应该被提取的表格特征

满足以下**任意一个**条件：
1. 第1行（列名行）中包含 `数据类型`、`类型`、`数据类型` 等字段类型关键词
2. 第0行（信息名称行）中出现 `信息名称`、`通信帧名称` 等标头关键词（说明是标准分布式表）
3. 数据行中出现 `UINTEGER`、`UINT`、`USHORT`、`FLOAT`、`bit` 等数据类型字符串
4. 表格的前置段落包含 `表XX` 格式标题（说明这是一个有明确标题的定义表）

### 9.2 应该被跳过的表格特征

满足以下**任意一个**条件：
1. 第1行不包含任何数据类型关键词，且数据行也不含任何数据类型字符串
2. 前置段落明确说明是"干扰表格"、"说明表"等
3. 表格是帧格式说明表（只有帧头、帧尾等抽象描述，无字段定义）
4. 表格是测试指令表（含"测试指令"、"是否带数据"等列）

### 9.3 端口分配表的识别

满足以下条件：
- 列名中包含 `信源系统码`、`信宿系统码`、`信源机器码`、`信宿机器码` → 这是端口分配总表（源表#2）
- 列名中包含 `消息ID`，且仅有5列左右 → 这是消息ID映射表（源表#3）

### 9.4 bit位定义表的识别

满足以下条件：
- 列名中包含 `位号`、`bit`、`状态参数` 等关键词
- 或列名为 `字节 | 位号 | 状态参数 | 取值说明 | 备注` 格式

## 十、输出 Excel 字体颜色规则

根据对 Excel 文件的分析，颜色使用规则如下：

### 10.1 正常颜色（主题色1，接近黑色）

Excel 中大多数单元格使用的是 **主题色 theme=1**，这在实际显示中接近黑色。

从分析结果看，几乎所有单元格都使用 `theme=1`，只有极少数是真正的"默认黑色"（`00000000`）。

**实际规则**：
- 正常单元格：使用默认字体颜色（不设置特殊颜色）或 theme=1
- **来自备注提取的值域**：使用红色字体（RGB: `FFFF0000`）

### 10.2 写入时的颜色逻辑

- 所有字段的普通内容：默认颜色（黑色）
- 判读公式列：
  - 来自源表"值域"列：默认颜色（黑色）
  - 来自备注列提取：红色字体 `FFFF0000`

## 十三、合并单元格的处理策略

### 13.1 水平合并（gridSpan）

原因：表头中同一列名横跨多列（如"内容"占两列，因为是相同列的重复）

**处理方式**：
- 读取单元格时，合并列的所有子列值相同（都是合并的主单元格值）
- 识别时只取第一个非重复出现的值
- 对于信息名称行（行0）：通过检测合并列来提取消息名称（排除固定表头词）

**固定表头词**（不是消息名称）：
`信息名称`、`通信帧名称`、`信息标识`、`上级信息名称`、`信息流向`、`—`、空字符串

### 13.2 垂直合并（vMerge）

原因：消息1表中父级名称跨行（`总信息` 对应 `信息1` 和 `信息2` 两行）

**处理方式**：
- `vMerge = 'restart'`：表示合并区域的开始，记录该值
- `vMerge = 'continue'`：表示合并区域的延续，该单元格的实际值等于上一个 restart 的值
- 处理时：向下遍历时，如果遇到 continue，用上面 restart 的值填充

## 十四、边界情况与特殊值处理

### 14.1 空值与占位符

| 源表值 | 处理方式 |
|-------|--------|
| `—`（长/短破折号） | 输出为空或 None |
| `""` 或空字符串 | 输出为 None |
| `序号` 列的空值 | 忽略（序号列本身不映射到任何输出列） |

### 14.2 重复行

- 源表 #4（检查结果）的 `计时时间` 字段在 Excel 中出现两次（行4、行5）
- 这可能是源文档中存在重复定义，或者是不同的通信方向各一行
- 处理方式：直接输出两行（不合并）

### 14.3 同名字段在不同消息下的处理

- `某设备计时时间` 在多个消息下重复出现
- 每个消息下都保留各自的定义，不合并
- 同名字段可能在不同消息中有不同的字节数、值域等，需保留各自的独立定义

### 14.4 单位为"—"的处理

- 当单位为 `—` 时，Excel 中该字段的单位列为空
- 不应将 `—` 写入 Excel

### 14.5 转换公式在备注中的情况

- 某些表（如测量数据1/2）的"数据处理"列写 `乘以10`
- 某些表的备注列写 `乘以10`（如帧计数的备注）
- 规则：优先从专用的"数据处理/数据转换方法"列提取；若该列为空但备注中有，从备注提取
- `乘以10` 转为 `10x`（或 `10x+0`）

## 十五、总体处理流程设计建议

1. **解析文档结构**：用 python-docx 读取文档，按顺序提取段落和表格，记录每个表格前的最近段落标题

2. **识别表格类型**：对每个表格判断是：端口分配表、消息ID表、字段定义表（A/B/C型）、bit位定义表、还是干扰表

3. **构建辅助字典**：
   - 消息名 → 系统码信息（来自端口分配表）
   - 消息名 → 消息ID（来自消息ID映射表）

4. **逐表处理字段定义表**：
   - 识别表头行（可能是1行或2行）
   - 识别列名（动态匹配）
   - 提取消息名称（来自信息名称行或前置段落）
   - 逐行提取字段信息
   - 处理合并单元格（水平合并去重、垂直合并展开）
   - 查询辅助字典获取系统码和ID
   - 处理值域（判读公式）、转换公式、单位等
   - 构建主行（第一字段）和子行（其余字段）

5. **处理联合表**：
   - 识别 bit 位定义表，将其附加到对应字段的后续子行

6. **写入 Excel**：
   - 使用 openpyxl 写入
   - 从备注提取的值域用红色字体标记
   - 其余内容用默认字体颜色

## 十六、需要注意的已知问题

1. **Excel行4-5重复**：检查结果消息的 `计时时间` 字段出现两次，属于正常（源文档有两处定义）
