# 字段配置使用说明

## 📁 配置文件

包含三个字段配置JSON文件，用于前端协议字段匹配：

### 1. 核心字段配置.json (推荐使用)
- 包含最常用的16个协议字段和16个目标字段
- 适合大多数文档处理场景
- 文件较小，加载速度快

### 2. 字段配置模板.json 
- 包含标准的15个协议字段和17个目标字段
- 适合一般文档处理需求
- 字段命名规范统一

### 3. 完整字段配置模板.json (新增)
- 包含完整的38个协议字段和26个目标字段
- 覆盖全面的字段类型
- 适合复杂文档处理和专业场景

## 🚀 使用方式

### 前端导入（推荐）
1. 访问前端界面：http://localhost:5174
2. 进入"字段配置"页面（路径：/#/config）
3. 点击"导入字段（JSON）"按钮
4. 选择JSON文件上传
5. 系统会自动按字段名称去重合并，保留现有字段并添加新字段

### 后端API管理
- 协议字段管理：`/api/config/protocol-fields`
- 目标字段管理：`/api/config/target-fields`
- 支持增删改查操作
- 数据持久化存储

### 配置文件说明
配置文件采用JSON格式，结构简单明了，可直接在前端界面导入使用。

## 📊 字段对应关系

### 协议字段 (Protocol Fields)
这些是从文档中提取的原始字段名称：

**基础字段（16个）：**
- 序号、参数、内容、信号名称
- 数据类型、类型、长度、字节
- 单位、备注、值域
- 信源、信宿、信息内容
- 消息ID、接口名称

**扩展字段（22个）：**
- 协议版本、校验和、时间戳、优先级
- 状态、方向、格式、编码
- 压缩方式、加密方式、路由信息
- 会话ID、事务ID、关联ID、序列号
- 分片信息、QoS等级、生存时间、跳数
- 源地址、目的地址、网关

### 目标字段 (Target Fields)  
这些是标准化的目标字段名称：

**基础字段（16个）：**
- ID、内容、转换类型、类型（bit）
- 信源系统码、信源机器码
- 信宿系统码、信宿机器码
- 子地址、备注、信息标识
- 信号名称、数据类型、字节数
- 单位、取值范围

**扩展字段（10个）：**
- 协议版本、校验和、时间戳、优先级
- 状态、方向、格式、编码
- 压缩方式、加密方式

## 🔧 自定义配置

如果需要自定义字段，可以：

1. 编辑JSON文件，添加或删除字段项
2. 保持JSON格式正确
3. 确保每个字段都有唯一的id和name

### 字段格式示例：
```json
{
  "id": "唯一标识符",
  "name": "字段显示名称"
}
```

## 💡 使用建议

### 用户类型推荐
- **入门用户**：使用"核心字段配置.json"（字段精简，处理速度快）
- **一般用户**：使用"字段配置模板.json"（字段标准，匹配准确）
- **专业用户**：使用"完整字段配置模板.json"（字段全面，功能丰富）
- **个性化需求**：基于现有文件修改调整

### 最佳实践
1. **首次使用**：建议从核心字段配置开始
2. **逐步扩展**：根据实际需求导入更完整的配置
3. **定期备份**：使用导出功能保存自定义配置
4. **版本管理**：为不同项目维护不同的配置文件

**注意事项**：
- JSON导入会自动按名称去重合并，保留现有字段并添加新字段
- 前端修改无需重启服务，即时生效
- 后端数据持久化存储，重启后配置不会丢失
- 支持手动添加、编辑、删除字段

## 🔧 技术细节

### 数据结构
```json
{
  "protocolFields": [
    {"id": "唯一标识符", "name": "字段显示名称"}
  ],
  "targetFields": [
    {"id": "唯一标识符", "name": "字段显示名称"}
  ]
}
```

### 合并策略
- 按字段名称（忽略大小写）进行去重
- 保留现有字段配置
- 仅添加新的字段项
- ID自动生成确保唯一性

### 存储方式
- 前端：localStorage（临时存储）
- 后端：JSON文件持久化存储
- 支持跨会话数据保持
