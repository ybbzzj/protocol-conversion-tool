# 字段配置文件使用说明

## 📁 文件说明

本目录包含两个字段配置文件，用于前端字段匹配功能：

### 1. 核心字段配置.json (推荐使用)
- 包含最常用的16个协议字段和16个目标字段
- 适合大多数文档处理场景
- 文件较小，加载速度快

### 2. 字段配置模板.json 
- 包含完整的38个协议字段和26个目标字段
- 覆盖更全面的字段类型
- 适合复杂文档处理需求

## 🚀 使用方法

### 方法一：前端导入（推荐）
1. 打开前端界面：http://localhost:5173
2. 进入"字段配置"页面
3. 点击"导入字段（JSON）"按钮
4. 选择对应的JSON文件上传

### 方法二：直接替换后端配置文件
```bash
# 备份原有文件
cp backend/config_protocol_fields.json backend/config_protocol_fields.json.backup
cp backend/config_target_fields.json backend/config_target_fields.json.backup

# 替换为新配置
# 需要从JSON文件中提取相应数组并保存为新的配置文件
```

## 📊 字段对应关系

### 协议字段 (Protocol Fields)
这些是从文档中提取的原始字段名称：

- 序号、参数、内容、信号名称
- 数据类型、类型、长度、字节
- 单位、备注、值域
- 信源、信宿、信息内容
- 消息ID、接口名称

### 目标字段 (Target Fields)  
这些是标准化的目标字段名称：

- ID、内容、转换类型、类型（bit）
- 信源系统码、信源机器码
- 信宿系统码、信宿机器码
- 子地址、备注、信息标识
- 信号名称、数据类型、字节数
- 单位、取值范围

## 🔧 自定义配置

如果需要自定义字段，可以：

1. 编辑JSON文件，添加或删除字段项
2. 保持JSON格式正确
3. 确保每个字段都有唯一的id和name

### 字段格式示例：
```json
{
  "id": "唯一标识符",
  "name": "字段显示名称"
}
```

## 💡 使用建议

1. **初学者**：建议使用"核心字段配置.json"
2. **专业用户**：可根据实际需求使用"字段配置模板.json"
3. **定制需求**：可基于模板文件进行个性化修改

## 🔄 更新配置

当需要更新字段配置时：
1. 修改JSON文件
2. 重新导入到前端
3. 或更新后端配置文件
4. 重启服务使配置生效

---
**注意**：导入时会自动合并去重，不会覆盖已有配置。
